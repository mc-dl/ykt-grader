# 脱敏说明与数据规范

本仓库源自一次真实课程的批改工作目录。公开前做了一次系统性清理，本文记录**删了什么、为什么删、以后怎么保持干净**。

## 1. 清理清单

| 原内容 | 处理 | 原因 |
|---|---|---|
| 浏览器用户目录（`profile/`，约 500 MB） | 删除 | 含 Cookie、历史记录、登录态、缓存的账号信息 |
| 学生作答附件（`att/`，约 620 MB） | 删除 | 学生手写作业原件，属于个人学习数据 |
| 网页截图（含姓名与分数） | 删除 | 直接暴露学生身份与成绩 |
| 花名册、逐人分数与评语日志 | 删除 | 姓名 + 网页标识 + 分数，可识别到个人 |
| 课程/班级/考试内部 ID、教师个人链接 | 改写为占位符 | 可定位到具体课程与班级 |
| 本机绝对路径、Windows 用户名、WSL 路径 | 改写为相对路径或占位符 | 暴露设备与账户信息 |
| 教材答案原文与扫描件、教师姓名 | 不入库 | 版权与第三方个人信息；只保留结论表与勘误 |
| 一次性调试脚本与中间产物 | 删除 | 不通用、含硬编码路径 |

清理后仓库只保留：流程文档、通用脚本、匿名案例、虚构示例、结论性答案表。

## 2. 占位符约定

写文档、示例、日志时统一使用：

| 类型 | 占位符 |
|---|---|
| 学生姓名 | `示例学生A`、`示例学生B` |
| 网页学生标识 | `105000001`（递增） |
| 课程/作业 ID | `<classroom_id>`、`<exam_id>` |
| 本机路径 | `data/att/<sid>/`、`<repo-root>` |
| 学校/班级 | `目标课程`、`目标班级` |

**真实标识只出现在本机 `data/` 里，不进入任何被提交的文件。**

## 3. 数据分级

| 级别 | 例子 | 存放 | 能否提交 |
|---|---|---|---|
| 公开 | 流程、评分档、结论表、脚本 | 仓库 | 可以 |
| 内部 | 课程 ID、作业 ID、教师姓名 | `config/` 本地或 `data/` | 不建议 |
| 敏感 | 学生姓名、学号、附件、分数、截图 | `data/` | **禁止** |
| 机密 | Cookie、Token、Chrome 配置、密码 | 浏览器/系统凭据 | **禁止** |

`.gitignore` 已覆盖 `data/`、`*.submitted.json`、`roster.json`、`manifest.json`、`report.json`、`results*.json`、`profile/`、`.env*`。

## 4. 日常使用规范

1. **只在 `data/` 里放学生数据**，需要临时目录时用 `YKT_DATA_DIR` 指到仓库外。
2. 不要用 `git add -f` 绕过忽略规则。
3. 截图、导出的 Excel/PDF 都算学生数据，不要放进仓库或聊天记录。
4. 批改结束后，按学校要求保留或删除 `data/`；至少不要让它在共享盘上长期裸放。
5. 换电脑时，迁移的是脚本与文档，不是 `data/`。
6. 提交前跑一次全文扫描（见下）。

## 5. 提交前自查

```bash
# 1. 看将要提交什么
git status --short
git diff --cached --stat

# 2. 确认没有数据目录
git ls-files | grep -E '^(data/|.*\.submitted\.json|roster\.json|manifest\.json)' && echo "有敏感文件！"

# 3. 扫描常见个人信息痕迹（中文姓名较难自动识别，重点看数字 ID 与路径）
git grep -nE '[A-Za-z]:\\Users|/home/[a-z]+/|classroom[_-]?id|exam[_-]?id' -- . ':!docs/privacy.md'

# 4. 扫描密钥类字符串
git grep -nEi 'cookie|token|password|secret|bearer' -- . ':!docs/*.md'
```

第 3、4 条命令在文档里也会命中说明性文字，逐条确认是"讲解"而不是"真值"。

另外建议人工过一遍：

- [ ] 没有真实姓名、学号、网页标识
- [ ] 没有课程/考试的内部链接
- [ ] 没有本机绝对路径或用户名
- [ ] 没有截图、附件、Excel 导出
- [ ] 示例文件全是虚构数据
- [ ] `LICENSE` 与使用边界已写明

## 6. 如果误提交了

1. 立刻删除文件并提交；
2. **改写历史**（`git filter-repo` 或重新初始化仓库），因为 Git 历史仍可检出；
3. 如果涉及 Cookie/Token，先在平台侧失效该凭据；
4. 如果涉及学生数据，按学校的数据事件流程上报，不要只删不报。

公开仓库一旦推送，删除最新提交并不等于数据消失——务必先改写历史再推送。

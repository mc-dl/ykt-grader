# 完整批改流程

本文是"人 + Agent + 脚本"共同遵循的作业流程。所有具体学生、课程 ID、链接都是占位符；实际操作以实时页面为准。

## 1. 建立当前页面上下文

1. 用 `node scripts/status.mjs` 列出标签页，选标题为"主观题批改"的那个。不要复用上一次会话的标签索引。
2. 如果出现登录页，说明调试用的 Chrome 配置没有登录状态：让用户在这个窗口里完成登录，**不要**尝试读取或搬运其他浏览器的 Cookie。
3. 已经打开目标标签时直接复用。重复点"去批改"会开出多个相同页面，后续容易写错标签。
4. 每轮操作前重新读页面，不缓存元素引用。

## 2. 找到课程与作业

典型路径（不同学校、不同学期可能不同）：

```
课程班级 → 我教的课 → 目标课程卡片 → 教学日志 → 第 N 章作业 → 去批改
```

注意：

- 课程卡片的标题、课程页标题、学期文案可能不一致，用**课程名 + 班级标签 + 人数**共同确认，不要只凭一个词判断。
- "去批改"通常**新开标签**，原页面不变化。此时重新列标签页，而不是反复点按钮。
- 批改页 URL 里带 `classroom` / `exam_id` 等内部参数，**只在本机使用**，不要写进公开文档或提交到仓库。

## 3. 读题干要求

1. 在批改页点"题干详情"，确认本次作业包含哪些题（例如"思维导图 + 六道计算题"）。
2. 注意页面可能显示"共 1 题 / 满分 10 分"——这表示"一个主观题提交框"，里面往往包含多道教材习题，**不是只有一道题**。
3. 记录硬性要求：是否要思维导图、是否要手写过程、是否要合并 PDF、是否禁止横转、单位与科学计数法要求。
4. 关闭弹窗后**重新读取页面状态**，再继续点击；弹层残留会拦截后续操作（脚本里会隐藏 `.dialog-problem`，但这只是兜底）。

## 4. 确定学生范围

- 作业汇总页的学生顺序与批改页左侧列表**通常不一致**。用户说"前 N 位"时，先声明依据（批改列表顺序 / 提交时间 / 指定名单），再执行。
- 姓名下方的数字是**网页学生标识**，不一定是学校学号；两者不要混用，记录时写清楚。
- 附件图标旁的数字含义随形态不同：`2` 可能表示 2 张图片；PDF 旁的 `52` 不一定是 52 页。**以实际打开后的页数为准**。
- 达到用户指定的人数立即停止，不"顺手多批几个"。

## 5. 逐份阅读

### 图片提交

- 在**中间作答区**滚动，不要滚左侧名单。
- 从第一页顶部看到最后一页底部，相邻截图保留重叠，避免漏题。
- 点击图片可能只弹出"圈画/批注"菜单，并不会放大；需要细节时用 `prep.py` 切半页或 `crop2.py` 放大。
- 思维导图可能在末页，也可能在首页；看完计算题不等于看完全部内容。

### PDF 提交

- 等解析完成再判断；"0% / 加载中"不是空白作业。
- PDF 有独立滚动区和页码输入框；页边距可能很大，不要看到空白就认为到底。
- 页码有时滞后（滚动后仍显示 1/3），以实际内容和附件页数为准。
- 查看器不出画布时，用 `node scripts/dlpdf.mjs <sid>` 下载原文件，再 `python scripts/python/pdfrender.py` 渲染。
- 少数作业是正文富文本里嵌的图片（`.answer__text img`），既不是附件也不是画布，`harvest.mjs` 已覆盖这种形态。

### 常见误判

| 现象 | 正确理解 |
|---|---|
| 大片白色 | 可能是页边距，继续往下看 |
| 显示"加载中" | 还没解析完，等 |
| 只有思维导图 | 可能是"仅导图"档，但要先确认没有第二份附件 |
| 内容是下一章习题 | 章节误传，按规则处理并提醒补交 |
| 图片旋转 90° | 先 `orient.py` 判断，再 `prep.py --rot-file` 逐页转 |

## 6. 对答案

1. 先核对**题目版本与参数**：同一题号在不同版次里电流、初值可能不同。
2. 再核对关键结果、方法与单位；等价表达式、合理舍入不扣分。
3. 参考答案本身可能 OCR 错、下标错、单位错。发现矛盾时回到元件和基本公式推导，不机械照抄。
4. 笔迹实在无法辨认的题，标记"待复核"，不要判错，也不要写"全部正确"。

## 7. 写评语与分数

网页"极速打分"开启时，流程是：

1. 在当前学生名下判断完毕，准备好分数与评语；
2. 先在评语框输入评语（未打分时提示"评语无法保存"是正常的暂存状态）；
3. 再输入分数并提交——**这一步就是提交，没有第二个"保存"按钮**；
4. 等待"正在保存"，确认出现"批改成功"、批改人数 +1、学生卡片显示分数；
5. 页面通常自动跳到下一位，评语框会清空；不要以为刚才的评语丢了而在新学生名下重输；
6. 读一下新学生的姓名/标识，确认换人成功再继续。

脚本 `submit.mjs` 已把这套动作固化：核对身份 → 填评语 → 精确写分 → 核验批改率/提示 → 写日志。人工操作时也按同样顺序。

要修改已评分学生：先选该学生，再走编辑入口；不要在"未打分"筛选下盲点分数。

## 8. 核验与收尾

- 用 `node scripts/roster.mjs` 导出已打分名单，检查人数与操作次数是否吻合。
- 抽查 1–3 位：重新打开，确认分数与完整评语确实保存（`node scripts/verify.mjs <sid>`）。
- 需要截图留证时，注意截图会包含学生姓名与分数，**只能保存在本地 `data/`**，不要发到群里或提交到仓库。
- 给用户的结果表：学生标识、分数、关键问题；说明已提交/仅建议、剩余人数、是否按要求停止。

## 9. 换章节时的检查清单

- [ ] 重新读题干，记录新题号与要求
- [ ] 找当次作业对应的本地参考答案，核对版次与参数
- [ ] 新建 `rubric.md`（可从 [`../examples/rubric.example.md`](../examples/rubric.example.md) 复制）
- [ ] 不要沿用上一章的题号、答案、作业 ID、人数
- [ ] 清空或另建 `data/results.json`，避免旧批次被重复提交
